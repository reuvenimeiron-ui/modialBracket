==================================================
PHASE 2 — DATA MODELS & TYPES
==================================================
Files: src/components/Scoring/scoringRules.types.ts + shared types

Interfaces:
- User          { id, displayName, email, totalPoints, predictionHistory }
- Tournament    { id, name, participants[], matches[], scoringRules, status }
- Match         { id, round, teamA, teamB, startTime, locked, result? }
- MatchResult   { finalScore, winner, leadingScorer }
- Prediction    { userId, matchId, predictedWinner, predictedScore,
                  predictedLeadingScorer, timestamp }
- ScoringRule   { ruleKey, points, enabled }

Allowed ruleKey values (STRICT):
  correct_winner | exact_score | goal_difference | leading_scorer

==================================================
PHASE 3 — SCORING ENGINE
==================================================
File: src/components/Scoring/scoringEngine.ts

- Pure function: (result, prediction, rules[]) => { totalPoints, breakdown }
- Apply rule only if enabled
- Rules stack (all enabled rules accumulate)
- No UI logic, no state mutation

==================================================
PHASE 4 — STATE MANAGEMENT (ZUSTAND)
==================================================
File: src/components/State/tournamentStore.ts

State:
  users[], currentUser, tournament, predictions[]

Actions:
  registerUser, loginUser, logoutUser,
  setPrediction, submitResult, lockMatch

Rules:
  - One prediction per (userId, matchId); setPrediction overwrites
  - submitResult: stores result, calls scoring engine, updates user.totalPoints
  - Leaderboard is DERIVED ONLY — never stored in state

==================================================
PHASE 8 — MATCH MODALS
==================================================
- src/components/Modals/MatchPredictionModal.tsx
    Inputs: predicted winner, predicted score, predicted leading scorer
    Disabled when match.locked === true
    Save calls setPrediction and closes modal

- src/components/Modals/MatchResultModal.tsx
    Enter final score, winner, leading scorer
    Submit calls submitResult → triggers scoring + leaderboard update
    No role enforcement (MVP)

==================================================
PHASE 9 — LEADERBOARD & SCORING RULES
==================================================
Leaderboard selector sorting priority:
  1. totalPoints
  2. exact score hits
  3. leading scorer hits
  4. earliest prediction timestamp

- src/components/Modals/LeaderboardModal.tsx    (read-only table)
- src/components/Modals/ScoringRulesModal.tsx   (read-only rules display)
