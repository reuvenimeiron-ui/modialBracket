PHASE L — SPORTS DATA: Real-Life Score Source
----------------------------------------------------------------
Category: External API integration
Prerequisite: Free API key from football-data.org (2 min signup)
Files:    src/services/footballDataApi.ts  (new)
          src/services/matchMapper.ts      (new)
          .env                             (new — store key here)

Step 1 — Get your key:
  Go to https://www.football-data.org/
  Sign up for the free tier (10 req/min, WC 2026 included)
  Copy your API key

Step 2 — Add to project:
  Create .env in project root:
    VITE_FOOTBALL_DATA_KEY=your_key_here
  Add .env to .gitignore (already ignored by Vite default)

What I build (footballDataApi.ts):
  - fetchMatchResult(teamA, teamB, date) → raw API response
  - Uses competition code "WC" and filters by team names
  - Returns null if match not finished yet

What I build (matchMapper.ts):
  - Maps football-data.org response → your MatchResult shape
  - Handles team name variants (e.g. "USA" → "United States")
  - Extracts leading scorer from top scorer stats endpoint
  - Returns null-safe result (match still in progress = null)

API response shape → your MatchResult:
  score.fullTime.home  → finalScore.teamA
  score.fullTime.away  → finalScore.teamB
  homeTeam.name        → winner (if score higher)
  scorers[0].player    → leadingScorer

Alternatives if football-data.org is unavailable:
  - API-Football (rapidapi.com)  — faster, paid after 100 req/day
  - ESPN unofficial API          — free, no key, may break
  - Manual entry via admin panel — already implemented

PHASE M — AUTO-FETCHER: Browser-Side Result Poller
----------------------------------------------------------------
Category: Background hook, no backend required
Files:    src/services/useAutoResults.ts  (new)
          src/App.tsx                     (wire hook)
          src/components/Users/DebugPanel.tsx  (status display)

What I build (useAutoResults.ts):
  A React hook that runs while admin is logged in:
    - Every 60 seconds, scans for matches that are:
        locked = true  AND  result = undefined
    - For each such match, calls footballDataApi.fetchMatchResult()
    - If result is ready (match finished), calls submitResult()
    - Logs every fetch attempt + outcome to the debug event bus
    - Exposes: { lastPollAt, pendingCount, fetchErrors[] }

Wired into App.tsx:
    useAutoResults();   // one line, runs silently in background

Debug Panel additions (new "🤖 Auto-Fetch" section in Events tab):
    - Last poll timestamp
    - How many matches are waiting for a result
    - Count of successful auto-submissions
    - Any fetch errors with full message

Polling safeguards:
  - Does nothing if no API key is set (fails gracefully)
  - Does nothing if tournament has no locked matches
  - Does not re-fetch a match that already has a result
  - Stops polling when all matches have results

Manual override:
  Admin can still submit a result manually via the bracket
  (overrides any auto-fetched result if needed)

PHASE N — AI LAYER: Smart Parsing & Name Matching
----------------------------------------------------------------
Category: Optional LLM augmentation (OpenAI / Gemini)
Prerequisite: OpenAI API key (or Gemini key)
Files:    src/services/aiResultParser.ts   (new)
          src/services/matchMapper.ts      (extend)
          .env                             (add key)

Important rule:
  NEVER use an LLM to get scores directly.
  LLMs hallucinate numbers. Use them ONLY to process text.

Use case 1 — Leading scorer extraction:
  football-data.org free tier does not always return scorer.
  Feed the raw match report text to GPT-4o-mini:
    Prompt: "From this match report, extract the player who
    scored the most goals. Return JSON: { player: string }.
    Report: {matchReportText}"
  Model: gpt-4o-mini (cheap, fast, accurate for extraction)
  Cost: ~$0.0002 per match

Use case 2 — Team name normalisation:
  API returns "United States Men's National Team"
  Your store has "United States"
  LLM maps the variant → canonical name reliably
  Alternative: a static alias map (no API cost, preferred)

Use case 3 — Match summary in prediction modal:
  After a result is submitted, show a 2-line AI summary:
    "Brazil beat France 2-1 in a tense affair. Vinícius Jr
    struck in the 67th and 89th minute to seal the win."
  Source: feed the raw scorer/event data to the LLM
  Displayed as a read-only blurb under the result in the modal

What I build (aiResultParser.ts):
  - extractLeadingScorer(matchReportText, teamA, teamB) → string
  - normaliseTeamName(rawName, knownTeams[]) → string
  - generateMatchSummary(result, events[]) → string
  - All calls are fire-and-forget with graceful fallback
    (if LLM fails, the result still saves without scorer/summary)

Add to .env:
  VITE_OPENAI_KEY=your_key_here
  (or VITE_GEMINI_KEY if using Google)

Cost estimate for 104 WC 2026 matches (gpt-4o-mini):
  Leading scorer extraction: ~$0.02 total
  Match summaries:           ~$0.08 total
  Total:                     < $0.15 for the whole tournament
